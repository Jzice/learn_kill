# 学堂杀 · 架构设计

> 本文档描述工程的模块划分、构建体系、数据流与联机协议设计，供开发者快速上手。
> 玩法规则见 [游戏机制.md](./游戏机制.md)。

## 1. 技术栈与总体形态

| 层 | 技术 |
|---|---|
| 语言 | TypeScript 5.6（strict，零 any 宽容编译） |
| 构建 | Vite 5 + vite-plugin-singlefile（单 HTML 产物） |
| 联机 | PeerJS 1.5（WebRTC DataChannel，房主权威架构） |
| 测试 | Playwright（playwright-core + 系统已装 headless chromium） |
| 运行时 | 无框架、无虚拟 DOM；全局状态对象 + 字符串模板全量重绘 |

产物形态：`npm run build` 一键产出两个**可直接双击打开**的单一 HTML 文件：

| 产物 | PeerJS 方式 | 体积 |
|---|---|---|
| `dist/学堂杀.html` | CDN `<script>` 标签 | ~157 KB |
| `dist/学堂杀.bundled.html` | npm peerjs 内嵌（联机可离线） | ~246 KB |

## 2. 构建体系

```
scripts/build.mjs      # 设置 VITE_PEERJS_MODE 后调 vite build（免 cross-env，Windows 友好）
scripts/dev.mjs        # 同理启动 dev server（node scripts/dev.mjs [cdn|bundled] [port]）
vite.config.ts         # 按 VITE_PEERJS_MODE 做三件事：
                       #   1) alias '#peer' → src/net/peer.cdn.ts 或 peer.bundled.ts
                       #   2) transformIndexHtml 仅在 cdn 模式注入 PeerJS CDN <script>
                       #   3) closeBundle 将 dist/index.html 重命名为模式对应文件名
src/index.html         # root=src，入口为 /main.ts
src/types/peerjs.d.ts  # 手写 PeerJS 最小类型（覆盖全局 window.Peer 与 module 'peerjs'）
```

双模式原理：业务代码统一 `import { getPeerCtor } from '#peer'`。CDN 模式下 alias 指向读取全局
`window.Peer` 的薄封装，Rollup 完全看不到 peerjs 包，产物不含其代码；bundled 模式 alias 指向
`import Peer from 'peerjs'` 的薄封装，正常打包。

├── globals.d.ts       # Window 接口声明（HTML 内联事件与动态模板所调函数）
├── index.html         # 大厅/对局界面骨架、四个弹窗、移动端 dock
├── style.css          # 全部样式（主题变量、响应式 900/600px 断点、特效动画）
├── core/              # 基础层
│   ├── types.ts       #   全部领域类型：Card/Player/Skill/Faction/Question/GameState + NetMessage 联合类型
│   ├── dom.ts         #   escapeHtml / sleep / inputValue / togglePanel；setSim/isSim 无头模拟开关
│   ├── sound.ts       #   WebAudio 振荡器合成音效（无音频资源）
│   └── fx.ts          #   DOM 动画特效层（飞牌/斩击/治疗/判定/阵亡；sim 下整体短路）

│   ├── factions.ts    #   九科阵营 + 主公技 + 科目图标

│   ├── cards.ts       #   牌堆构成与洗牌
│   ├── skilldefs.ts   #   【新增】技能登记表 SKILL_DEFS：46 角色 93 技能 + 9 主公技 + 18 学科主题技；defOf / skillOf
│   ├── banks/         #   【生成】按年级拆分的题库配置 g01..g12.ts + manifest.ts（清单+动态加载器映射）

│   ├── actions.ts     #   出牌（杀/桃/酒/锦囊/装备）与出闪
│   ├── skillEngine.ts #   【新增】声明式技能统一分派器（见 §3.1）：defOf/skillsOf/canPay/fire/invokeActive/runEffects/canConvertAs
│   ├── skills.ts      #   主动技能入口薄封装（答题门槛+日志+FX+showPlayHint → 转发 invokeActive；扩展包走 skillfx）
│   ├── skillfx.ts     #   扩展包 SkillEffect 原语执行 + 求和聚合（与引擎加法式共存）
│   ├── turn.ts        #   回合流程（判定→摸牌→参悟→出牌→弃牌）；埋 17 个技能时机钩子

│   ├── choice.ts      #   waitChoice：本地/远程选择的 Promise 桥（含心跳重发）

│   ├── marks.ts log.ts chat.ts

├── profile/           # localStorage 档案（积分/段位/成就/个性化资料）+ 结算

**循环依赖约定**：ui ↔ game ↔ net 存在函数级循环引用，ESM 下安全的前提是——
除 `main.ts` 外任何模块不得有顶层副作用（不得访问他模块的顶层绑定）。

### 3.1 声明式技能引擎（v2.0 新增）

技能不再按 id 写死在 `skills.ts` 的 switch 里，而是**数据驱动 + 统一分派**：

- `data/skilldefs.ts` 的 `SKILL_DEFS` 是一张 `id → SkillDef` 登记表。角色 `skills[]` 只存 id，
  由 `skillOf(id)` 在装配时派生出 `Skill`（单一数据源；规则书 / 选人卡 / 亮将卡都从这里取描述）。
- `SkillDef = { id, name, kind, timing, desc, cost?, limit?, cond?, effects[] }`：
  - `timing`（20 个时机）：`active / passive / onTurnStart / onDraw / onTurnEnd / beforeJudge / beforeDamage / onDamaged / onTargetSha / onUseShan / onShaHit / onUseTrick / onTrickCountered / onLoseHand / onDeath / awaken …`
  - `effects`：一组效果原语（牌堆操控 / 转化 / 杀闪交互 / 点数花色 / 交互博弈 / 状态标记 / 资源，共约 44 种）。
  - `SkillE = SkillEffect & { at? }` 允许一条定义把不同原语挂到不同时机（如觉醒替代技合并手牌上限 + 受伤摸牌）。
- `game/skillEngine.ts` 是唯一分派器（**禁止顶层副作用**）：`fire(timing, ctx)` 按时机过滤 → 校验 `cond`/`limit` → 支付费用 → 执行原语；
  主动技走 `invokeActive`（答题门槛 → 扣 limit → 付费用 → 原语 → 同步）。`canConvertAs` 供出牌区与 `requestShan` 查询「该手牌可否当目标牌」。
- 所有玩家选择一律走 `choice.ts` 的 `waitChoice`（联机 Promise 桥）；`sim` 模式下 `waitChoice` 自动按默认规则结算。
- **向后兼容**：108 个扩展包角色是 `SkillEffect` 原语制，未登记到 `SKILL_DEFS` 的 id 会回退到 `skillfx.ts` 执行，扩展包数据零改动继续工作。
- `Player` 新增 `skillUse / skillGame / marks / turnSuits`，`PlayerFlags` 新增 `pledge / playedCount / dealtDamage / usedTrick / lastCardType`；
  均随 `state_sync`（players 全量序列化，无字段白名单）下发到客人端，须保持 JSON 安全。

### 3.2 无头模拟（balance.mjs / smoke-skills.mjs 用）

`core/dom.ts` 的 `setSim(true)` 是全局开关：开启后 `sleep` 立即返回、`FX` 整体短路、`render()` 提前返回、
`Sound.play` 跳过、`waitChoice` 自动按默认值结算（技能发动按 AI 概率 0.62）。
`main.ts` 挂载 `window.xtsSim / xtsMakeAllAI / xtsSnapshot / xtsSkillAudit / xtsAutoRun` 供无头脚本驱动批量 AI 对战。
`scripts/balance.mjs` 每局独立 `evaluate` 调用 `xtsAutoRun(1, seats)` 跑一局并累计，输出各身份 / 各角色胜率与「去身份实力」分档表。

## 4. 渲染模型

单一状态驱动：所有 UI 从全局 `G`（`game/state.ts`）派生，由 `ui/render.ts` 的 `render()` 全量重绘。
交互提示与按钮由 `G.pendingOptions / pendingType / pendingPlayer` 三个字段派生；
手牌是否可点击由 `isCardClickable()` 依据当前待决选择判定。所有 mutate 路径最后调用 `render()`。

## 5. 联机协议（房主权威）

```
Guest                              Host（唯一事实源，运行 gameLoop）
  │ hello_profile(档案) ──────────────▶ 加入 roomMembers，广播 room_state
  │ ◀────────────── room_state ────────│（成员列表：昵称/头像/性别/心情/段位）
  │ ◀──── start_game(players,myIdx) ───│ 开局（players 已附带各自 identity）
  │ ◀────────────── state_sync ────────│ 全量快照（80ms 防抖 scheduleSync）
  │ ◀────────────── choose_request ────│ 轮到客人做选择（含 4s 心跳重发）
  │ choose_response ──────────────────▶│ resolve waitChoice 的 Promise
  │ ◀────────── ask_quiz_request ──────│ 房主要求客人答题（带 quizId）
  │ quiz_response(quizId,correct) ────▶│ 按 quizId 匹配，迟到旧回复丢弃
  │ ◀──────── play_log / chat ─────────│ 增量广播
```

关键设计点：
- **有序可靠信道**：`peer.connect(dest, { reliable: true })`。协议依赖消息顺序（旧 state_sync 不得后置
  覆盖新 choose_request），无序信道会造成双端状态错位死锁。
- **quizId 防串扰**：远程答题 20s 超时定时器在响应后清除；迟到回复按编号丢弃。
- **掉线自愈**：连接关闭 → 玩家转 AI；若房主正等待其选择/答题，按默认项/答错立即结算，不挂起。

## 6. 题库按年级懒加载

```
scripts/extract-bank.mjs  ──生成──▶  src/data/banks/
                                       ├── g01.ts ... g12.ts   # 每年级一个模块（默认导出题目数组）
                                       └── manifest.ts         # GRADE_BANK_META（年级+题数清单）
                                                               # GRADE_LOADERS（年级名 → () => import('./gNN')）
```

- **零成本渲染**：大厅年级按钮的题数来自清单（manifest），不加载题目本身。
- **按需加载**：`bankLoader.loadGrade(grade)` 动态 `import()` 对应模块并写入运行态 `QUESTION_BANK`，
  带并发去重（inflight map）与失败兜底；`startSingle/hostStartGame` 开局前 `await loadGrade(所选年级)`。
- **外部题库**：URL/本地导入合并进 `QUESTION_BANK`（去重按题干），支持创建清单之外的年级。
- **单文件产物说明**：`vite-plugin-singlefile` 会将动态 import 的 chunk 内联回单文件（体积不省），
  但模块工厂仍**延迟执行**——数据在首次被请求时才解析；dev 模式下则为真正的网络级懒加载
  （`scripts/verify-lazy.mjs` 可验证：初始 0 个年级模块，开局仅加载所选年级 gNN.ts）。

## 7. 个性化资料

| 字段 | 说明 | 存储 | 同步 |
|---|---|---|---|
| name | 昵称（≤12 字） | localStorage `xuetangsha_profile_v1` | hello_profile / room_state |
| avatar | 自选 emoji 头像（24 选） | 同上 | 同上 |
| gender | 男生 / 女生 / 保密 | 同上 | 同上 |
| mood / moodIcon | 一句话心情（≤24 字）+ 图标（24 选） | 同上 | 同上 |

流转：大厅「个性化资料」面板编辑 → `PROFILE`（profile/）→ `publicProfile()` 序列化 →
联机成员列表（`rm-item` 行内展示头像/性别/心情）→ 开局时经 `identityFromProfile` 写入
`Player.identity` → 对局座位卡展示（自定义头像、性别角标、心情行）。AI 玩家 `identity=null`，
回退显示角色头像。

## 9. 1:1 复刻不变量（改动前必读）

1. `G` 字段形状不可变——`state_sync` 直接 JSON 序列化，客户端结构化解包。
2. 模板字符串中调用的函数必须挂载到 `window`（main.ts）并在 `globals.d.ts` 声明。
3. 模块顶层禁止副作用；初始化统一收口 `main.ts init()`。
4. 魔法数字为行为的一部分：80ms 同步防抖、20s 答题超时、1.5s 答题反馈、牌堆构成、
   `xts-` 房间号前缀、AI 概率（0.6/0.62/0.55）、奖励概率档（0.30/0.55/0.72/0.88）。
5. 题库唯一数据源为 `data/questions/<年级>/<科目>.tsv`（原版单文件的内置基线题已于 v1.7.4 迁移为各科 TSV 首段），由 `npm run build:banks` 生成 `src/data/banks/`，请勿手改生成物；`docs/` 下另见
   [架构设计.md](./架构设计.md) 与 [游戏机制.md](./游戏机制.md)。
