# 扩展包学习解锁机制设计（v2.x）

> 本文件为本机制的唯一设计依据。游戏内实现与数值以本文档 + `src/` 代码为准。
> 相关：学分经济基线见 [学分商店学习激励方案.md](./学分商店学习激励方案.md)；联机同步见 [架构设计.md](./架构设计.md)。

## 1. 需求背景

原「扩展包」（初中 / 高中 / 全部）仅作为角色池筛选器，无使用门槛。现将其与学习行为挂钩：使用扩展包须满足一定学分条件，从而鼓励用户通过**答题、复习错题**积累学分并持续掌握学科知识点。

用户原始诉求要点：
- 全部 / 不同年级的扩展包须满足学分条件方可使用，与学习机制挂钩；
- 预留次数限制，**每天 3 次扩展包免费机会**，超出后每次须答题 / 复习获取学分解锁；
- 联机时各用户**按自身情况自主决定**扩展包，不受房主限制，增加竞争；
- **默认「按年级」解锁不受限制**（永久免费）。

## 2. 已拍板的四项决策

| # | 决策点 | 结论 |
|---|---|---|
| Q0 | 哪些包需门槛 | 仅 `junior` / `senior` / `all` 三包；`grade`（按年级）永久免费 |
| Q1 | 解锁方式 | **纯按次付费，不永久解锁**（每日 3 次免费，超出每局按次扣学分，长期反复付费） |
| Q2 | 免费粒度 | 三包**共享**每天 3 次计数器 |
| Q3 | 联机模型 | **统一选包 + 个人叠加**；中途加入按 AI 角色接管，重开前可重选 |

### 2.1 关键调和说明（务必阅读）

Q1 明确「**不永久解锁**」，而 Q3 中使用了「已解锁 all 者」措辞。两者统一口径为：
**「解锁」在联机语境下 = 「本局已启用（通过免费次数或按次扣学分）」，而非持久拥有扩展包。**
即玩家每次开局用到扩展包，都要重新结算一次（免费优先，否则扣学分）。若后续希望改为「一次性永久解锁」，需另开需求，本方案不实现。

## 3. 数值表

| 包 `PacketId` | 名称 | 阶序 `packetRank` | 每局档位 `PACK_TOLL`（学分） | 每日免费 | 说明 |
|---|---|---|---|---|---|
| `grade` | 按年级 | 0 | 0 | 不限 | 永久免费；角色池随年级累加，不追加学科主题技能 |
| `junior` | 初中扩展包 | 1 | 20 | 共享 3/日 | 初中角色全部 + 初中主题技能 |
| `senior` | 高中扩展包 | 2 | 30 | 共享 3/日 | 高中角色全部 + 高中主题技能 |
| `all` | 全部 | 3 | 50 | 共享 3/日 | 含所有角色，不分年级 / 学段 |

- 免费计数器：`PROFILE.packUsage = { date, used }`，上限 `PACK_FREE_DAILY = 3`，按日期跨日自动重置（范式同 `creditDaily`）。
- 计费取值：**取本局有效池中的最高阶扩展包**档位（基础包 ∪ 个人叠加的并集里的最高 `packetRank`）。例：基础 `grade` + 叠加 `all` → 按 `all`(50) 计费；基础 `senior` + 叠加 `junior` → 按 `senior`(30)。

## 4. 计费归属与联机结算

### 4.1 谁为哪个包付费

- **单机 / 房主**：为自己在设置界面选定的**基础包**（`SELECTED_PACKET`）付费（若是扩展包）。
- **联机加入方**：仅为**自己叠加启用的扩展包**（`PlayerPref.packets`）付费；房主选定的基础包由房主自行结算，加入方**不代付、不代查**。
  - 推论：若房主选 `all` 作基础包，加入方使用它**免费**（房主已结算），加入方若再叠加则继续为自己的叠加付费。该设计促使房主默认选 `grade`（免费），鼓励个人按需叠加 —— 符合「增加竞争、各人自主」。

### 4.2 扣费时机（各客户端本地自结算）

- 单机：`startSingle()` 开局前结算基础包。
- 房主：`hostStartGame()` 开局前结算基础包。
- 加入方：收到房主 `start_game` 时，结算自身 `SELECTED_EXTRA_PACKETS`。
- 学分不联机同步（见架构设计 §9.7.1），因此付费为**本地自校验**：UI 在「启用前」即阻止不可负担的包（置灰），开局时各客户端必然可负担；`PlayerPref.packets` 即为已付费内容，房主据此组池，无需回退降级。

### 4.3 重开 / 中途加入

- **重开**：每局重新结算（每次启用都付费）。加入方在「重新开局前」可重新勾选已启用扩展包内的角色。
- **中途加入**：直接接管某一 AI 座位既有角色（沿用该座位的 AI 角色），不触发新选包、不重复扣费。

## 5. 组池算法（每座位独立）

```
effectiveCharPool(grade, base, extra):
  seen = {}
  add(mergedCharPool(grade, base))        // 复用现有「基础池 + 已学分解锁扩展角色」规则
  for p in extra where p != base:
      add(mergedCharPool(grade, p))
  return values(seen)                      // 去重合并
```

- 房主 `setupPlayers`：房间总池 = `effectiveCharPool(年级, 基础包, 所有成员叠加包并集)`（供 AI 座位抽取）；每个远程座位再按其 `pref.packets` 取独立座位池分派角色，并用 `used` 集合避免多座位重复。
- 角色池规模固定（≤81），纯函数、无题库懒加载，保持性能不变量。

## 6. UI 设计（大厅显著翻新，非新页面）

沿用暗色卡牌 / 玻璃拟态 / 霓虹强调美术语言：

1. **扩展包选择区（packetPicker）**：四枚选项横向排列。`grade` 常驻「免费」高亮；三扩展包按钮右上角状态徽标——免费剩余时「免费 X/3」、需付费时「💰 档位/局」、不可负担时「🔒 锁定」。
2. **每日免费额度条（packMeter）**：胶囊进度「🎟️ 今日扩展包免费 X/3」，剩余/用尽用颜色区分；不可负担时「📖 去学习赚学分」按钮高亮脉冲引导（跳转题库浏览 / 刷题）。
3. **个人叠加开关区（extraPackPanel，联机加入方可见）**：`junior` / `senior` / `all` 三枚多选开关，选中即计入本局池；未达门槛的开关置灰并附「去学习赚学分」引导。
4. **角色预览提示**：随启用包实时变化「当前可选角色池共 N 名（基础 + 已叠加扩展包）」。

交互：悬停抬升 + 边框发光；锁定态去饱和置灰、点击微震并弹「去学习」引导。

## 8. 验收清单

- [ ] 单机选 `grade`：永久免费，无扣费、无免费计数变化。
- [ ] 单机选 `junior`/`senior`/`all`：每天前 3 次免费（计数 +1），第 4 次起扣对应档位学分；学分不足且免费用尽时禁止选择并引导去学习。
- [ ] 跨日：`packUsage.date` 变更后，免费计数重置为 0/3。
- [ ] 联机房主选 `grade` 基础包，加入方叠加 `all`：加入方角色池 = 基础 ∪ all，加入方为 `all` 付费（免费优先），房主不代付。
- [ ] 联机组池一致性：房主与各客户端角色池一致；多座位不重复角色。
- [ ] 中途加入：接管 AI 角色，不重复扣费。
- [ ] 重开：重新结算付费；加入方可在重开前改选。
- [ ] `dist/学堂杀.html` 单文件内联、`verify-dist` 通过；`typecheck` / `build` / `smoke` / `smoke-net` 全绿。
